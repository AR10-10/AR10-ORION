1Visão de produto

AR10 Cyborg 2.0 — iPad One-Tap Cloud Runtime continua um PWA standalone, local-first, aberto com um único toque direto no Safari do iPad via HTTPS. Esta entrega adiciona três capacidades novas sobre a base já existente: (1) um botão único ("Preparar Cyborg neste iPad") que automatiza download, verificação, instalação, replay e diagnóstico numa só ação; (2) uma camada de voz real (Siriform Voice Layer) para os mesmos comandos seguros já existentes; (3) documentação honesta da rota futura para um modelo de linguagem da família Meta Llama.

Princípio inegociável, reafirmado nesta entrega com uma lei nova: nenhuma ação no painel — por toque, por voz, ou por uma futura integração Siri/Apple Intelligence — executa ordem, abre posição, conecta em corretora ou guarda segredo.

3Mockup real recebido — como foi usado

Diferente da entrega anterior, esta missão recebeu uma imagem real de referência (screenshot do Safari no iPad, URL cyborg.ar10.io): layout em duas colunas — barra superior, coluna esquerda com cards de status/instalação, centro com o Siriform Avatar + microfone + ações rápidas, coluna direita com painéis de status, log e seletor de perfil na base.

A missão concedeu liberdade técnica total ("não é uma prisão pixel-perfect"). Decisão tomada: implementar um grid CSS responsivo de 2/3 colunas (@media (min-width: 900px) e @media (min-width: 1300px)) usando atribuição direta de grid-column por id existente — sem duplicar ou reordenar nenhum elemento do DOM. Em telas estreitas (iPad retrato, iPhone), tudo cai numa única coluna na ordem natural do documento, com o Siriform sempre em primeiro lugar — exatamente a experiência já validada antes desta entrega.

Alternativas descartadas e o motivo: grid-row: 1 / -1 (índices negativos de linha) tem histórico de incompatibilidade no Safari/WebKit; sobrescrever grid-row com números "mágicos" grandes poderia criar lacunas visuais indesejadas quando as colunas têm alturas de conteúdo muito diferentes. A solução adotada aceita um risco cosmético menor (lacunas de auto-posicionamento em telas muito largas) em troca de zero risco de compatibilidade e zero mudança na ordem de leitura/acessibilidade do documento.

4ONE-LINK IPAD RUNTIME — Preparar Cyborg neste iPad

Pipeline de um toque (handlePrepareCyborg() em js/app.js), reaproveitando os mesmos primitivos seguros já existentes — nenhuma rota de execução nova foi criada:

  1. Baixa o pacote local, se ainda não estiver carregado nesta sessão.
  2. Verifica SHA-256 de cada arquivo — aborta imediatamente (retorno antecipado, estado fail_closed) se qualquer hash não bater, antes de qualquer instalação.
  3. Instala no Safari Storage (OPFS → fallback IndexedDB).
  4. Reinicializa o motor WASM defensivamente.
  5. Roda o Replay BTC/USDT (reaproveita handleRunReplay()).
  6. Roda o Diagnóstico Offline (reaproveita handleRunDiagnostics()).
  7. Reporta sucesso na legenda do Siriform e no log.

Um catch-all cobre qualquer outra falha não prevista, sempre caindo em fail_closed — nunca em um sucesso silencioso ou otimista demais.

5Siriform Voice Layer (implementada agora)

Web Speech API (SpeechRecognition) + Web Speech Synthesis, pt-BR, janela de escuta única (não contínua). Arquivo: js/voice.js, consumido por js/app.js.

8 comandos permitidos (verificar safari, preparar cyborg, rodar diagnóstico, rodar replay, mostrar status, explicar análise, mostrar modo de segurança, como adicionar à tela de início) — cada um despachado para a mesma função que o botão equivalente na tela já usa (dispatchVoiceCommand), nunca uma rota paralela de execução.

7 frases bloqueadas por política, checadas com prioridade máxima sobre qualquer comando permitido: comprar · vender · abrir ordem · fechar ordem · operar real · usar chave · conectar conta real.

Resposta obrigatória, idêntica em texto e voz:

"Execução real está bloqueada. O Cyborg está em READ_ONLY / FAIL_CLOSED."

Detalhe completo (tabelas de comandos, estados de voz, nota de privacidade) em docs/APPLE_INTELLIGENCE_AND_SIRI_ROUTE.md.

7Meta Llama / WebLLM Route (FUTURE)

Nome correto da família: Meta Llama (não "Llama" genérico). Realismo por variante: Llama 4 Scout (candidato mais realista para iPad/Safari, ainda exige quantização agressiva), Llama 4 Maverick (referência de capacidade, tamanho normalmente incompatível com on-device em iPad), Llama 4 Behemoth (modelo professor da Meta, citado só como referência de proveniência — nunca candidato a rodar no iPad).

Engines candidatos, todos FUTURE: WebLLM/MLC-LLM (700–4000 MB), Transformers.js (20–300 MB), ONNX Runtime Web. Cadeia de fallback declarada termina em FALLBACK_TEXT_ONLY — que é o que está ativo hoje: todo o Siriform já responde com lógica determinística, sem nenhum modelo.

Motivo de não embutir modelo nesta versão: tamanho incompatível com um pacote base de download único e sem fricção, armazenamento OPFS/IndexedDB do Safari com políticas de eviction variáveis, WebGPU não universal em todas as versões suportadas, e exigência de consentimento explícito para download de múltiplos GB — esse fluxo ainda não existe.

Análise completa, tabela de status, e listas "PODE/NUNCA" em docs/META_LLAMA_WEB_NATIVE_ROUTE.md e pack/manifest.models.json.

8Arquitetura iPad/Safari

  • PWA: manifest.webmanifest + service-worker.js cache-first/offline-first, same-origin — cache version cyborg-ipad-runtime-v3 nesta entrega (precache de js/voice.js adicionado).
  • Voz: js/voice.js — só interpreta (matchCommand), nunca executa; despacho para os mesmos handlers dos botões em js/app.js.
  • Layout responsivo: grid CSS 2/3 colunas por grid-column direto em ids existentes, sem reordenar o DOM (ver seção 3).
  • CSP restritiva inalterada: script-src 'self', connect-src 'self', object-src 'none' — a camada de voz não abre nenhuma exceção nova na CSP (nenhum fetch/XHR em voice.js).
  • Motor de cálculo: Rust → WASM em Web Worker, inalterado nesta entrega.
  • Pacote local .ar10pack: inalterado nesta entrega (payload intacto, checksums confirmados).

13Motivo do HOLD e ação manual necessária

A API REST POST /repos/{owner}/{repo}/pages (criar um site do GitHub Pages pela primeira vez) exige permissão de administração do repositório, que o GITHUB_TOKEN automático de uma Action nunca tem — trava do próprio GitHub, não do workflow. Reconfirmado nesta sessão: nenhuma ferramenta MCP do GitHub disponível habilita Pages ou contorna essa exigência.

  1. Abrir github.com/AR10-10/AR10-ORION/settings/pages com conta admin.
  2. Em Build and deployment → Source, selecionar "GitHub Actions".
  3. Salvar — cria o site do Pages uma única vez.
  4. Reexecutar o workflow (push tocando ipad_runtime/**, ou Actions → Run workflow).
  5. Confirmar que https://ar10-10.github.io/ar10-orion/ responde 200.

Detalhe completo em docs/GITHUB_PAGES_FIX.md.
