1Visão de produto

AR10 Cyborg 2.0 — iPad One-Tap Cloud Runtime é um PWA standalone, local-first, pensado para abrir com um único toque direto no Safari do iPad via HTTPS — sem Mac Mini, sem MacBook, sem servidor próprio, sem terminal e sem ZIP como fluxo principal.

É um sub-produto do organismo maior AR10 ORION V5.0 (Cockpit Python completo, ver README.md da raiz do repositório) — compartilha a identidade visual "Ciborgue", mas é deliberadamente menor em escopo: uma vitrine read-only para verificar capacidades do Safari, instalar um pacote local verificável, rodar diagnóstico 100% offline e visualizar um replay BTC/USDT sintético com estatística real calculada em WASM.

Princípio inegociável do produto: nenhuma ação no painel executa ordem, conecta em corretora ou guarda segredo — o valor entregue é transparência e verificação local, não automação de trading.

3Como a referência visual foi usada

Transparência total: nenhuma imagem foi efetivamente recebida como anexo nesta sessão de execução — apesar da missão mencionar uma imagem de referência, o conteúdo da mensagem continha apenas texto. A "liberdade de redesenhar sem copiar pixel-a-pixel" concedida pela missão foi usada para traduzir a descrição textual (nomes de componentes, frases exatas do Siriform, lista de badges, lista de botões, lista de campos de status) na estrutura visual entregue.

Decisão de design: manter a paleta "Ciborgue" já existente no Cockpit (--long-green #00FF9D, --short-red #FF3E52, --sys-cyan #00F2FF, --alert-amber #FFB800, fundo #000000) e sobrepor a sub-marca "Nebula Core" — um orbe central (conic-gradient + radial-gradient em pseudo-elementos, sem canvas/imagem) como ponto focal, com cards em grade abaixo. Se uma imagem real de referência for fornecida em uma próxima sessão, a arquitetura CSS já é orientada a data-state e variáveis — permite re-skin sem tocar a lógica em js/siriform.js ou js/app.js.

4Arquitetura iPad/Safari

  • PWA: manifest.webmanifest (display standalone) + service-worker.js cache-first, offline-first, só same-origin.
  • Armazenamento local: OPFS com fallback automático para IndexedDB (js/storage.js) — sem depender de suporte específico de uma versão de iPadOS.
  • Motor de cálculo: Rust → WASM (wasm-src/cyborg_quant_core/, cdylib, wasm32-unknown-unknown), ~3.6 KB, roda dentro de um Web Worker (workers/quant-worker.js) — nunca bloqueia a UI thread.
  • CSP restritiva em index.html: script-src 'self' (sem unsafe-eval), connect-src 'self', object-src 'none', frame-ancestors 'none' — bloqueio em nível de navegador para qualquer rota de rede para fora da própria origem.
  • Pacote local .ar10pack: container JSON UTF-8 (não ZIP), com manifestos + checksums SHA-256 + payload em base64 — parsing nativo, zero dependência externa, zero eval().
  • Replay BTC/USDT: dataset sintético ("kind": "SYNTHETIC_OFFLINE_SAMPLE", "live": false), gerado por random-walk com seed fixa — nenhuma chamada de rede/exchange.

9Motivo do HOLD

A API REST POST /repos/{owner}/{repo}/pages (criar um site do GitHub Pages pela primeira vez) exige permissão de administração do repositório. O GITHUB_TOKEN automático recebido por uma Action nunca tem essa permissão, mesmo com pages: write declarado no workflow — essa é uma trava do próprio GitHub, não uma falha de configuração deste repositório ou do workflow.

Reconfirmado nesta sessão: nenhuma das ferramentas MCP do GitHub disponíveis (lista completa pesquisada via ToolSearch antes deste documento) expõe uma operação de habilitar Pages ou renomear repositório. Depois que o site existir (criado uma única vez por um humano com permissão de admin), todo deploy futuro via Action funciona sem nenhum passo manual adicional.

10Ação manual necessária (GitHub Pages)

  1. Abrir github.com/AR10-10/AR10-ORION/settings/pages com uma conta admin do repositório.
  2. Em Build and deployment → Source, selecionar "GitHub Actions".
  3. Salvar.
  4. Reexecutar o workflow (push novo tocando ipad_runtime/**, ou Actions → Run workflow).
  5. Confirmar que https://ar10-10.github.io/ar10-orion/ responde 200.

Detalhe completo em docs/GITHUB_PAGES_FIX.md.

11Regras de segurança (leis obrigatórias)

Permanentemente bloqueado, sem exceção, sem rota técnica no código:

real trading · live trading · MT5 order_send · MEXC private endpoint · API Secret · private keys · segredo em localStorage · ordem por LLM · ordem sem Risk Gate · CDN para núcleo sensível · eval() · PASS enganoso sem link HTTPS.

Sempre visível na UI:

READ_ONLY FAIL_CLOSED Execution Lock: ACTIVE Private Keys: DISABLED Live Trading: BLOCKED

Aplicação técnica, não apenas rótulo visual: CSP sem unsafe-eval e connect-src 'self' (bloqueio em runtime de qualquer fetch/WebSocket para fora da origem), DecisionFrame sem nenhuma lógica de decisão implementada (STUB CONTROLLED), Vault que re-verifica SHA-256 a cada boot em vez de confiar numa flag salva.
